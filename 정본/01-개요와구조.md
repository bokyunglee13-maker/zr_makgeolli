# 01 — 개요와 구조

> 제품이 무엇이고, 어떻게 구성·동작·배포되는지. (구 PRD + MEMORY의 구조/아키텍처)

## 1. 개요
- **무엇**: 두타몰 B2F 'ㅈㄹ막걸리 × DOOTA' 팝업 행사용 다국어(한·영·일·중) 정적 사이트 + 부가 페이지.
- **누구**: 내국인 + 외국인 방문객(설문은 외국인 대상).
- **톤**: 브루탈리스트 + 키치, 핑크 무드 ("Kinetic Pink" — [02-디자인](02-디자인.md)).
- **기간/장소**: 2026.6.8 – 6.30 · 두타몰 B2F(서울 중구 장충단로 275) · 14:00–24:00(MON–SUN) · 무료 입장.
- **슬로건**: `DRINK HAPPY NOT HEAVY` (한 줄, 푸터 포함 전역).

## 2. 파일 맵 & 라우트
```
index.html            # 랜딩 (4개 언어 i18n 내장)
name.html             # Korean Alphabet Name 생성기 단독 페이지

survey.html           # 시음·브랜드 설문 (4개 언어, 기본 en)
assets/chosung.js     # ★ 초성 변환 엔진(공유) — index/name이 <script src>로 로드
apps-script/Code.gs   # 구글시트 백엔드 (gift / survey / namegen / 레거시 응모 분기)

```
| 라우트 | URL |
|---|---|
| 랜딩(언어별) | `/`, `/ko` `/en` `/ja` `/zh` (기본 ko) |
| 생성기 단독 | `/name` (+`?lang=`) |

→ 언어별 QR을 따로 만든다. 언어 토글 = 국기 아이콘(flagcdn kr/us/jp/cn, EN=미국기).

## 3. 아키텍처
- **정적 사이트(빌드 없음)** → Vercel. 백엔드 = **Apps Script 웹앱**(구글시트 DB). 페이지마다 독립 HTML(인라인 CSS/JS).
- 프론트 → `fetch(CONFIG.WEBAPP_URL, {method:'POST', body:JSON.stringify(payload)})`. payload `type`로 시트 분기. JSON 문자열 본문·커스텀 헤더 없음 → "simple request"(프리플라이트 없음), 응답 무시(fire-and-forget).
- 동일 `WEBAPP_URL`을 **index/survey/name 3곳 `CONFIG`에 입력**. (✅ 연결·적재 검증, Vercel Analytics Enable.)
- **이미지 경로는 반드시 `/assets/...`(루트 절대)** — `/en` `/survey/ja` 등 하위경로 라우트에서 상대경로가 깨지지 않게.

### 3-1. i18n 규칙
- 각 페이지에 `I18N = {ko,en,ja,zh}` 사전 + `[data-i18n]`(index) / `[data-k]`(survey/name) 요소 + `applyLang(lang)`가 textContent/innerHTML, `[data-i18n-ph]`/`[data-k-ph]` placeholder 교체.
- 언어 감지 `detectLang()`: 경로 `/(ko|en|ja|zh)` > `?lang=` > localStorage(`zr_lang`) > 기본(index=ko, survey/name=en).
- 줄바꿈 = 문자열에 `\n` + 해당 요소 CSS `white-space:pre-line`.
- **카피 수정 시 HTML 기본값과 I18N 사전을 둘 다** 고친다. 마크업이 든 값(브랜드 반반색·`<br>`)은 `innerHTML`로 렌더.

### 3-2. 초성 변환 엔진 `assets/chosung.js` (공유, 언어별 분기)
전역 `toChosung(name, lang)`. (index/name 중복 로직을 한 파일로 추출 → 동기화 불필요.) 단어별로 ①한글/자모→직접 초성 ②`NAME_MAP[키]` 있으면 사용 ③없으면 언어별 로마자 함수. **lang은 입력 이름의 언어가 아니라 UI 언어** — 한글은 항상 직접 처리, NAME_MAP이 교차 폴백.
- **`NAME_MAP`**: 불규칙 표기 예외(한국 성씨 kim·park·choi, 영·일·중 흔한 이름). 최종 안전망.
- **ko/en 공용 `romanLatin(word,{silentE})`**: 자음 디그래프(zh/sh/ch/ts) + 모음 이중자 `VOWEL_DI`(eo/eu/ae/oe/ui/oo/ou/ee/ea)=한 음절 + 중복자음 흡수. 받침 흡수 집합 `CODA=ㄱㄴㄹㅁㅂㅇㅎㅋ`(ㅋ=/k/는 ㄱ받침), 그 외(ㄷㅌㅅㅈㅊㅍ)는 '으'음절로 살림(Edward→ㅇㄷㅇㄷ). **en만 `silentE`**(자음+어말 e 묵음: nicole→ㄴㅋ).
- **ja `romanize_ja`(모라)**: 모든 모음=음절, 묵음 없음. 어두 무성음 k/t/ch→ㄱ/ㄷ/ㅈ, 어중→ㅋ/ㅌ/ㅊ(외래어표기법). f→ㅎ, ts→ㅊ, 장음 한 음절, っ/ん 코다. (takano→ㄷㅋㄴ, fukuda→ㅎㅋㄷ, watanabe→ㅇㅌㄴㅂ)
- **zh `romanize_zh`(병음 분해)**: 성모+운모, 복운모(ai·ei·ao·ou·ui·iao·uai)는 ㅇ 추가. 그리디 분해(xiaoming→ㅅㅇㅁ, wangfei→ㅇㅍㅇ, lixin→ㄹㅅ).

## 5. 핵심 기능
### 5-1. Korean Alphabet Name 생성기
입력 이름 → `toChosung(name, LANG)` 한글 초성. 결과 = **스토리 카드(1080×1920 Canvas)** + 보틀 누끼(`bottle-cut.png`) → [이미지 저장]/[인스타 공유](Web Share). 단독 페이지 `/name`도. placeholder=언어별 흔한 이름(KO 김민지/EN EMMA/JA HIMARI/ZH XINYI). 예시: `JANG WON YOUNG → ㅈ ㅇ ㅇ`, `JUNGKOOK → ㅈ ㄱ`, `Rihanna → ㄹ ㅎ ㄴ`.

### 5-2. SNS 인증 기프트 뽑기(가챠) — APPLY
플로우: ①@zr.makgeolli 팔로우 → ②스토리+@멘션 → ③아이디 입력·인증 체크 → 랜덤 기프트. **확률**: 🔑 키링 10% · 🪞 거울 40% · 🏷️ 할인쿠폰 50%(`GIFTS` 가중 `drawGift()`). 코드: 서버(`type:'gift'`)가 행번호 기반 `ZR-K/M/D-####`. 결과 버튼 = 이미지 저장(메인) + 공유·팔로우·닫기. 저장 = 기프트 티켓 캔버스(1080×1350, `drawGiftTicket()`). **검증**: 웹 자동검증 불가 → 현장 스태프 육안 확인. **인스타 아이디 미저장**(payload `instagram:''`), 동의 체크박스 없음. 데이터 → `gifts` 시트.
- **zh(중국) 변형**: 인스타 불가 → 小红书(RED) 흐름. 상세·이유는 [03-변경이력](03-변경이력.md).

### 5-3. 이름 궁합 (match.html, 한국어 전용)
두 한글 이름 → 한글 획수 궁합(초/중/종성 분해→자소 획수 합→두 이름 교차 배열→인접합 mod 10 반복→2자리 점수). chosung.js와 별개(자체 내장, 한글 전용). 양방향 `getScore(A,B)`/`(B,A)` → 각자 기준 점수, 헤드라인=평균. 키치 연출(획수 카운트업→게이지→점수 카운트업→점수대 이모지·멘트 6단계). 스토리 카드(1080×1920) 저장/공유. 로깅 = `namegen` 시트 재사용(event=`match_*`, name=`A × B`, chosung=점수, page=`match`). 검증: 배성재×장예원=77, 장원영 기준 93·안유진 기준 73.

### 5-4. 시음·브랜드 설문 (survey.html, 외국인 대상)
문항: ①기본(국적·성별) ②맛 만족도(필수 1~5) ③디자인·가격(1~5) ④재구매 ⑤자유 의견. 4개 언어, 기본 en. 데이터 → `survey` 시트.

## 6. 데이터 모델 (구글시트)
한 웹앱이 `type`으로 분기: `gift` / `survey` / `namegen` / (default=레거시 `responses`, 미사용·보존).
- `gifts`: timestamp · instagram(빈값) · gift · followed · story · code · language
- `survey`: timestamp · language · nationality · gender · overall · design · price · repurchase · comment
- `namegen`: timestamp · event(`generate/share/save`, 궁합은 `match_*`) · name(궁합은 `A × B`) · chosung(궁합은 점수) · language · page(`index/name/match`)
- `Dashboard`: `buildDashboard()`(시트 메뉴 [📊 ZR > 대시보드 갱신])가 KPI 요약 — 생성수·인기 이름 TOP10·공유/저장 전환율·설문 평균·국적/성별 분포·기프트 실제 비율.
- **분석 2단**: ①구글시트 `namegen`(원본 이름) ②Vercel Analytics 커스텀 이벤트(이름 없이). `logName()`이 둘 다 발사. 안내문 `gen.track`(4언어).

## 7. 배포 절차
1. **Apps Script**: 구글시트 → Apps Script에 `Code.gs` 붙여넣기 → 배포→웹앱(실행:나 / 액세스:모든 사용자) → URL 획득.
2. `CONFIG.WEBAPP_URL`을 index/survey/name 3곳에 입력. (미입력 시 화면 정상, 폼 제출만 비활성.)
3. GitHub push → Vercel 자동 배포(또는 `vercel`). Framework: **Other**(빌드 없음).
4. 코드 수정 시 Apps Script는 **배포 관리 → 새 버전** 재배포(URL 유지). 시트 헤더 변경 시 시트 삭제 후 재생성.
5. **대시보드**: `onOpen`/`buildDashboard`/`getRows_`는 시트 바운드 함수 → 웹앱 재배포 불필요, 메뉴 실행만.
